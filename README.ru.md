# Autoreg — автоматизация регистрации аккаунтов для AI-агентов

[English](README.md) | **Русский**

**Скилл для агента и Python CLI для повторяемых сценариев регистрации и подтверждения почты.**

Autoreg превращает процесс регистрации на сервисе в многоразовый YAML-адаптер. Он объединяет работу через браузер и HTTP, получение OTP из почты, постоянные профили аккаунтов, маршрутизацию через прокси, проверку и шифрованное хранение учётных данных в рамках одного проекта.

**Первый релиз:** 1.0.0 · **Автор и сопровождение:** [@ikhdev](https://t.me/ikhdev)

[Скачать последний релиз](https://github.com/Ikhdev1/autoreg-agent-skill/releases/latest) · [Инструкции для агента](SKILL.md) · [Справочник адаптеров](references/adapters.md)

## Возможности

- **Анализ регистрации:** изучение форм, элементов управления, запросов и признаков защиты; формирование отчёта и заготовки YAML-адаптера.
- **Работа через браузер и HTTP:** интерактивные сценарии на Patchright, Playwright, Camoufox или опциональном `invisible_playwright`; `curl_cffi` для протокольных сценариев.
- **Подтверждение почты:** получение кодов и ссылок через Voidash, mail.tm, mail.gw, IMAP, Outlook Graph, Cloudflare Workers или настраиваемый HTTP-провайдер.
- **Постоянный контекст аккаунта:** отдельный профиль браузера, ящик и назначенный прокси для каждого аккаунта; повторное использование этого контекста при повторных попытках.
- **Отложенное подтверждение:** сохранение аккаунта со статусом `pending`, затем восстановление его зашифрованной почтовой сессии в отдельном процессе `verify` без пропуска писем, пришедших между запусками.
- **Интеграции CAPTCHA:** подключение 2captcha, YesCaptcha, локальных сервисов или ручного прохождения. Vision и распознавание речи используют отдельно настроенные API моделей.
- **Инструменты взаимодействия:** действия по селекторам, ввод с нативными событиями, раздельные поля OTP, управление мышью через CDP и клики по скриншоту.
- **Шифрованное хранение:** защита паролей, учётных данных прокси и почтовых сессий с помощью Fernet в SQLite; экспорт аккаунтов в JSON, CSV или JSONL.
- **Диагностика:** проверка окружения, журнал выполнения, снимки состояния при сбоях, проверка согласованности отпечатка браузера и локальный сервер для сквозных тестов.

В репозитории находятся **8 шаблонов адаптеров** и **14 справочных материалов**. Адаптеры описывают отдельные сервисы, а движок выполнения остаётся общим.

## Установка

Требуются **Python 3.13** и браузер, установленный для выбранного движка. Docker не нужен.

### Установка из Git

```bash
git clone https://github.com/Ikhdev1/autoreg-agent-skill.git "$HOME/.agents/skills/autoreg"
python -m pip install -r "$HOME/.agents/skills/autoreg/requirements.txt"
python -m patchright install chromium
```

### Установка из ZIP релиза

Скачайте `autoreg-agent-skill-1.0.0.zip` из [первого релиза](https://github.com/Ikhdev1/autoreg-agent-skill/releases/tag/v1.0.0). В архиве находится корневая папка `autoreg/`. Распакуйте её в каталог скиллов вашего агента, например `~/.agents/skills/`.

Затем установите Python-зависимости и выбранный браузер командами выше. В релизе также находится `SHA256SUMS.txt` для проверки контрольной суммы архива.

Для Windows PowerShell:

```powershell
Expand-Archive .\autoreg-agent-skill-1.0.0.zip -DestinationPath "$env:USERPROFILE\.agents\skills"
python -m pip install -r "$env:USERPROFILE\.agents\skills\autoreg\requirements.txt"
python -m patchright install chromium
```

`SKILL.md` — точка входа для агентов с поддержкой локальных скиллов. В других клиентах настройте путь поиска скиллов или загрузите этот файл напрямую. После установки начните новую сессию агента.

### Дополнительные движки

`invisible_playwright` устанавливается отдельно:

```bash
python -m pip install invisible-playwright
```

Выберите его явно через `--engine invisible`. В обычном режиме `auto` приоритет отдаётся Patchright; адаптеры с `stealth: true` предпочитают Camoufox, если он доступен. Для Camoufox необходимо отдельно скачать браузер:

```bash
python -m camoufox fetch
```

## Быстрый старт

Запускайте команды из каталога проекта, в котором будут храниться данные регистрации:

```bash
AUTOREG="$HOME/.agents/skills/autoreg/scripts/autoreg.py"

python "$AUTOREG" --home . init
python "$AUTOREG" --home . doctor
python "$AUTOREG" --home . recon https://target.example/signup
```

Изучите созданный отчёт и заготовку адаптера, затем настройте необходимые провайдеры почты, прокси, CAPTCHA или моделей. Готовый адаптер храните в `.autoreg/adapters/`.

```bash
python "$AUTOREG" --home . run .autoreg/adapters/target.yaml --count 1 --headed
python "$AUTOREG" --home . verify .autoreg/adapters/target.yaml --account 1
```

Префикс команд для Windows PowerShell:

```powershell
$AUTOREG = "$env:USERPROFILE\.agents\skills\autoreg\scripts\autoreg.py"
python $AUTOREG --home . doctor
```

`--home` принимает каталог проекта или его папку `.autoreg/`. Параметр `--json` включает машиночитаемый вывод и может находиться до или после подкоманды. Сообщения о ходе выполнения направляются в stderr.

## Команды

| Команда | Назначение |
|---|---|
| `init` | Создать данные проекта, конфигурацию по умолчанию, ключ шифрования и шаблоны адаптеров. |
| `doctor` | Проверить зависимости, движки, конфигурацию и хранилище. |
| `recon URL` | Снять состояние страницы регистрации, создать отчёт и заготовку адаптера. |
| `run ADAPTER` | Выполнить адаптер с настройками числа аккаунтов, параллельности, движка, прокси и переменных запуска. |
| `verify ADAPTER` | Повторно проверить один аккаунт или выбранную группу с использованием сохранённого контекста. |
| `accounts list/show/export/delete` | Просмотреть, экспортировать или удалить записи аккаунтов. |
| `profile new/list/show/delete/fpcheck` | Управлять профилями браузера и проверять согласованность отпечатка. |
| `adapters validate PATH` | Проверить указанный адаптер; `--all` проверяет доступные шаблоны. |
| `mail test --provider NAME` | Проверить доступ к почте; `--wait` включает получение кода. |
| `proxy check URL` | Проверить выходной IP прокси и географические данные. |
| `selftest` | Проверить регистрацию, OTP, подтверждение и хранилище на локальном тестовом сервисе. |

Полный список параметров команды доступен через `--help`.

## Данные проекта и отложенная проверка

Код скилла отделён от данных проекта. Рабочие данные находятся в `<project>/.autoreg/`: база, ключ шифрования, профили, журнал выполнения и сохранённые снимки.

Параметр `mail.defer: true` пропускает немедленное подтверждение и сохраняет аккаунт со статусом `pending`. При последующем запуске `verify` из зашифрованного хранилища восстанавливаются исходная конфигурация почты, токен, метаданные и набор исключённых ID писем. Новый ящик вместо прежнего не создаётся.

Восстановленные сессии и аккаунты со статусом `pending` не обновляют набор исключённых писем автоматически. Явный шаг `mail_arm` позволяет зафиксировать новый набор перед запросом следующего письма. Сохранение почтовой сессии не продлевает срок хранения ящика у провайдера или срок действия токена.

Подробнее: [двухфазная регистрация и подтверждение](references/two-phase.md) и [почтовые провайдеры](references/mail.md).

## Проверка работы

Подтверждённый набор проверок — **44 модульных и 10 сквозных тестов**. Сквозные проверки используют встроенный локальный тестовый сервис: регистрация через браузер, протокольные сценарии, отложенное подтверждение через ящик с токеном доступа, recon, действия ввода и тестовые сценарии vision-интеграции.

```bash
cd ~/.agents/skills/autoreg
python -m unittest discover -s tests -p "test_core.py" -v
python -m unittest discover -s tests -p "test_e2e.py" -v
```

Полная локальная проверка через CLI:

```bash
python scripts/autoreg.py --home /tmp/autoreg-selftest selftest --engine patchright
```

Встроенные тесты не подтверждают совместимость со всеми сторонними сервисами. Для новой цели нужны адаптер, доступ к необходимым провайдерам и фактический прогон регистрации с подтверждением. SMS сейчас подключается через hook; встроенного SMS-провайдера нет. Модели vision и распознавания речи, подписки провайдеров и браузерные бинарные файлы в ZIP не включены.

## Учётные данные и локальные файлы

- Храните ключи провайдеров в переменных окружения или локальном `.env`, а не в адаптерах, добавленных в Git.
- Ключ `.autoreg/key` расшифровывает базу аккаунтов. Храните его вместе с защищённой резервной копией; не добавляйте ключ и базу в репозиторий.
- Экспорт аккаунтов не включает учётные данные почтового ящика. Для экспорта пароля требуется явный параметр `accounts export --secrets`.
- Автоматические логи OTP и извлечения значений сообщают об их наличии, а не выводят сами коды, темы писем или извлечённые учётные данные. Явная команда `mail test --wait` возвращает запрошенный код.
- Профили браузера, HAR, сохранённый HTML и скриншоты — локальные рабочие данные. Шифрование базы не распространяется на эти файлы.
- Локальные данные, учётные данные и кэш исключены из репозитория. Shell-скрипты сохраняют окончания строк LF при клонировании в Windows.
- Адаптеры могут выполнять Python-hooks; проверяйте внешние адаптеры перед запуском.
